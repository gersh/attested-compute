This is the single accounting gate for every root in the last completed
`claude_math` axiom print for
`Math.Problems.TernaryGoldbach.ternary_goldbach`. It joins:

- the three Lean foundations (`propext`, `Classical.choice`, and
  `Quot.sound`);
- all thirteen named external/source atoms; and
- all 1,371 native-generated roots in fifteen closed families.

The resulting partition has 1,387 roots, of which 1,384 are computational or
source dependencies addressed by the replacement program. The foundations
are not physical finite computations and are not routed through an Azure
receipt.

Run the production-data-free catalog audit with:

```bash
python3 tools/audit_tg_full_trust_boundary.py
```

When the exact sibling checkout retaining the last-fresh build artifact is
available, also audit the authority itself:

```bash
python3 tools/audit_tg_full_trust_boundary.py \
  --claude-math-root ../claude_math
```

The second command pins all three artifact hashes, parses the exact
`#print axioms` report from `Statement.trace`, and requires a bijection with
the native trust manifest. It handles Lean's current-namespace elision and
private-name `✝` suffix only through a unique full-name suffix match. It also
requires:

- a bijection between the thirteen trace source atoms, the citation
  inventory, and the compact checker catalog;
- exact family counts for all 1,371 native entries; and
- recomputation of every family membership digest from sorted declaration
  name and type digest pairs;
- one fail-closed member-status row for every native root; and
- exact agreement between the member rows and all fifteen family
  counts/digests;
- a closed aggregate architecture invocation for all 1,371 roots and all
  1,214 source decisions; and
- the generic, fail-closed receipt/refinement/checker composition, without
  treating that routing layer as a mathematical proof.
- the exact eleven-campaign closed source-program audit: the ten external
  campaigns plus the specialized Ramaré fallback, with zero campaigns
  promoted from an inner Boolean kernel to a complete program; and
- when the sibling source tree is supplied, the exact downstream all-native

- the exact closed accepted-receipt roster: ten external campaign fields plus
  one all-native aggregate field, both required physical-outcome projections,

Thus “all roots are accounted for” is true; “all roots are discharged” is
not. The thirteen external roots now have a theorem from their ten fixed
registered physical outcomes plus ten explicit universal executable
refinements. That is a conditional physical bridge, not evidence that a
refinement or outcome exists.

Every native family now has the same closed aggregate physical identity and a
generic composition theorem which avoids local production replay. The
downstream package also fixes the fifteen-family conjunction and instantiates
`FixedDecisionProgram.certificate` as
`CompactAllNativeInputs.deterministicProgramCertificate`. That is a genuine
source-level program-to-checker proof, but it is not a C/ELF/x86-64 program,
compiler theorem, loader theorem, ISA refinement, installed run, or receipt.
The downstream `CompactDeterministicProgramRoster.RemainingPrograms`
therefore still has exactly eleven fields, matching the local audit catalog.

A native target location is likewise deliberately weaker than a theorem
equivalence: the member crosswalk records 1,371 staging targets but asserts
zero statement-identity proofs, live integrations, or retirements. In
particular, six inaccessible private Lemma-3.7 decisions are routed to public
Q96 predicates with ordinary soundness theorems for the same real consumer
inequalities. They are semantic consumer replacements, not syntactically
identical reconstructions of the private historical root types.

## Execution policy

Routine local builds must not replay source-scale arithmetic. The thirteen
named atoms have compact checker-to-source projections, and all fifteen
native families have fixed source-decision bundles. The downstream aggregate
has a deterministic Lean source program for that fixed conjunction. Its
source-only aggregate, roster, and two conditional capstones were freshly
compiled on 2026-07-24 in about four seconds each without evaluating any
fixed decision; their main theorem closures contain exactly the foundational
trio. It has not been compiled and refined as a physical CPU executable. The
aggregate architecture route is available for all fifteen families when
direct checker replay is too large. The three 100-million/140-million Ramaré
folds additionally retain their narrower specialized invocation. Both routes
use the same single closed attested-execution axiom as the external
campaigns. No per-claim or per-family axiom is allowed.

“Mapped” is still not “proved.” No exact executable/ISA refinement or
reviewed receipt is installed. A typed receipt slot is only a place where a
future literal, reviewed receipt can be connected; it is not itself an
accepted receipt. The aggregate source check is being kept separate from
production-scale dependency replay. A fresh full build remains the only
authority for retirement.

At the code-proof layer,
`DeterministicProgramObligationRoster.lean` now enumerates all twelve physical
registry constructors: ten external campaigns, the all-native aggregate, and
the Ramaré fallback. Each field requires a total byte-program plus an ordinary
proof that successful output refines its fixed checker.

[`ClosedSourceProgramCatalog.lean`](../../SparkInterval/TernaryGoldbach/ClosedSourceProgramCatalog.lean)
then audits the eleven non-aggregate fields. It resolves useful inner
arithmetic kernels, but records the exact missing closed generator, artifact
parser/binding, total campaign Boolean, and
`check = true → nativeChecker.accepts canonicalInput canonicalResult`
theorem for every incomplete campaign. CDEM Abel now has the one complete
data-only artifact parser, total Boolean checker, and ordinary
artifact-acceptance-to-source theorem. The machine-checked result is therefore
10 required proof-program gaps and 1 concrete artifact program. An inner
`Certificate.check` or chunk replay is not counted as a program when the
source-scale evidence and canonical-acceptance bridge are still absent.

The downstream
`CompactAllNativeDeterministicProgram.lean` supplies the twelfth, aggregate
source-program field symbolically. This does not turn CDEM's source program
into an exact executable refinement, and it does not inhabit the complete
twelve-field roster: all eleven audited physical fields remain required.
No source program in this accounting has an installed static-CPU
compiler/loader/ISA certificate.

[`ClosedAcceptedReceiptRoster.lean`](../../SparkInterval/TernaryGoldbach/ClosedAcceptedReceiptRoster.lean)
separately fixes the eleven proof-authorizing receipt slots: the ten external
physical campaigns and the all-native aggregate. Its
`externalPhysicalOutcomes` and `nativeAggregatePhysicalOutcome` theorems
project only the preferred registered-architecture outcome. The optional
Ramaré three-fold fallback remains outside `RequiredRoster`. No receipt data
is present: the closed registry has no reviewed run, and
`no_current_requiredRoster` proves that the eleven-field roster is currently
uninhabited. Therefore the audit reports 11 closed slots, 0 imported
receipts, and 0 accepted receipts; it does not report discharge.
