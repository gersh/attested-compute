# Platt windowed zeta: source-semantic transform stage

[`h100_tg_platt_windowed_semantic.cu`](../../gpu/platform/h100/h100_tg_platt_windowed_semantic.cu)
implements the transform dataflow in `zeta_arb/arb_zeta.cpp` and
`zeta_arb/arb_fft.h` from `djplatt/code` commit
`42b21426718e542daa2b006dc05ea2d7f26426e6`.  It is intentionally separate
from the Taylor work-shape benchmark.  Its output claim is only

```text
source_semantic_transform_from_certified_input_boxes_not_a_zeta_certificate
```

The runner currently receives in-memory synthetic boxes.  Production must
replace those boxes with hash-bound, independently checked gamma and `skn`
packets.  Consequently this runner does **not** discharge the zeta-RH atom.

## Exact source map

Let `N1=32768`, `K=23`, and let `DFT+` and `DFT-` denote the unnormalised
positive- and negative-sign transforms used by Platt.

For every `k=0,...,22`, the runner performs the following operations.

1. Starting from the certified gamma row, it constructs
   `g(t;k)/k!` by the source recurrence
   `g_(k+1)=g_k*(-2*pi*i*t)/(k+1)`.
2. It adds the square complex error `1.83e-44`, applies `DFT-`, multiplies
   indices `0..N1/2` by the exact dyadic `21/128`, adds the square error
   `1e-307`, negates odd indices, and zeroes indices above `N1/2`.  This is
   `G_k`.
3. It applies `DFT+` independently to `G_k` and to the bucketed `skn` row,
   multiplies the resulting boxes pointwise, applies `DFT-`, divides by
   `N1`, and adds the retained indices over all 23 Taylor rows.  This is
   `make_skn`, `my_convolve`, and `do_conv` after the `skn` input boundary.
4. It overwrites Fourier bins `N1/2..N/2` with the square `Fmaxerr` box
   `3.93e-245`, adds the published `fhatsumerr=3.26e-33`,
   `tayerr=6.73e-33`, and `fhattwiderr=1e-307` boxes, and negates odd bins.
5. It executes `arb_fft.h::hermidft` literally: endpoint packing, conjugate
   pairs, the `e(n/(2NN))*i` multiplier (including the odd-index `omega`
   factor), one positive length-65536 DFT, and real/imaginary interleaving.

Positive roots are generated by MPFR `sinpi`/`cospi` on the exact dyadic
argument `2j/L` and rounded outward to binary64.  This avoids treating a
rounded approximation to pi as an exact root.

All non-dyadic reciprocals in the gamma recurrence are likewise generated as
MPFR-directed input boxes.  The device path contains no division: its numeric
instructions are directed finite add/subtract/multiply plus non-NaN min/max,
which is the arithmetic subset already modeled by the PTX refinement layer.
[`h100_tg_platt_windowed_semantic_ptx_audit.py`](../../gpu/platform/h100/h100_tg_platt_windowed_semantic_ptx_audit.py)
fails on any other floating-point arithmetic opcode, missing directed pair, or
round-to-nearest add/subtract/multiply.  The local CUDA 13.0 PTX had symmetric
counts (`35` directed adds each way, `9` subtracts, and `156` multiplies) and
no floating-point division, reciprocal, square root, FMA, or transcendental.

The source-sized operation counts are therefore exactly:

| operation | count per window |
|---|---:|
| negative `G_k` transforms | 23 |
| positive convolution transforms | 46 |
| negative normalized inverse transforms | 23 |
| positive final Hermitian transform | 1 |
| radix-2 butterflies | 23,134,208 |
| pointwise complex interval products | 753,664 |

The small `N1=8, K=3` known-answer run is compared against a separately
written direct long-double DFT implementation.  Every reference component is
contained by the CUDA interval output.

## Benchmark

On the local NVIDIA GB10, CUDA 13.0, with contraction disabled and directed
division enabled, the command

```bash
/tmp/sparkinterval-tg-platt-windowed-semantic \
  --source-shape --repetitions=128
```

measured `80.27` complete transform stages/s and `1.857` billion
butterflies/s.  This includes all four transforms for every Taylor row,
pointwise multiplication, normalization/Taylor summation, published error
insertions, and the final `hermidft`; it excludes term accumulation, gamma
evaluation, interpolation, and Turing work.  The input is source-shaped
synthetic data, not an actual zeta window.

At that GB10 rate the `2,966,443,783`-window high campaign would take `427.7`
device-days, or `53.46` days on eight equal devices.  The transform stage alone
therefore needs at least `7.64x` GB10 throughput on each of eight H100s to fit
seven days.  This is a required uplift, not an H100 prediction; a two-limb
arithmetic replacement would also increase work per butterfly.

## Binary64 usefulness result

The source-shaped synthetic run produced finite intervals but a maximum final
width of about `0.158`, with 430 of 131,072 synthetic samples containing zero.
The input stages were scaled by `2^(-13k)` to model the source residual-power
cancellation.  These counts are not an estimate of actual zeta ambiguity,
because the gamma and Dirichlet boxes are synthetic.  They are nevertheless a
clear warning: plain rectangular binary64 intervals lose substantial
precision through the four-transform cancellation.  The result must not be
interpreted as evidence that binary64 will isolate source zeros.

The next implementation should use at least a two-limb midpoint with a proved
outward radius (or a checked 128-bit fixed-point/expansion format), then replay
only genuinely ambiguous windows with Arb.  A physical H100 benchmark is also
required; GB10-to-H100 scaling is not evidence of the production rate.

## Remaining certificate boundaries

- Define and hash a packet containing the actual gamma and all 23 `skn` rows,
  their precision, window centre, source constants, and producer proof.
- Validate every input endpoint and a proved intermediate-magnitude budget,
  and retain a device failure flag for non-finite intermediates.  Checking only
  final finiteness is insufficient because IEEE min/max can suppress a NaN
  operand; the current synthetic-only executable is not an adversarial packet
  verifier.
- Extend the Lean radix-2 theorem to compose scale, pointwise product,
  normalized inverse DFT, Taylor sum, and `hermidft` packing.
- Bind the CUDA instruction trace to that checker; the present source is an
  implementation and benchmark, not a formally accepted physical trace.
- Measure actual-source interval usefulness at both endpoint heights and on a
  random interior sample before projecting fallback rates.
- Implement interpolation, sign/zero isolation, Turing completeness, campaign
  continuity, and the prefix below `10^10`.

The executable and its known-answer auditor can be built without changing the
repository build graph:

```bash
nvcc -O3 -std=c++20 -arch=sm_90 --fmad=false --ftz=false \
  --prec-div=true --prec-sqrt=true -Igpu/include -I$MPFR_INCLUDE \
  gpu/platform/h100/h100_tg_platt_windowed_semantic.cu \
  -L$MPFR_LIB -lmpfr -lgmp -o platt-windowed-semantic
python3 tests/tg_platt_windowed_semantic_known_answers.py \
  --runner ./platt-windowed-semantic
cuobjdump --dump-ptx ./platt-windowed-semantic > semantic.ptx
python3 gpu/platform/h100/h100_tg_platt_windowed_semantic_ptx_audit.py \
  --ptx semantic.ptx
```
